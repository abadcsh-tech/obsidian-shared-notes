고급과정 2기·3기 — 2주차: 에르메스 데스크탑과 Bases

1. 에르메스 설치·실행

다운로드: https://hermes-agent.nousresearch.com/desktop

  • Mac: macOS 12 이상, Apple Silicon. Intel Mac은 공식 미지원.
  • Windows: Windows 10·11.
  • 이미 Hermes를 설치했다면 기존 환경에서 실행:
hermes desktop

모델 연결: Settings → Providers에서 기존 ChatGPT/Codex 연결 확인 → Settings → Model에서 모델 선택 → 한국어로 첫 대화.

화면에서 확인할 것: 새 대화 / 모델 선택 / 파일 첨부 / 도구 실행 표시 / 중지 / 결과 미리보기.

2. Obsidian 연결 확인

볼트 경로와 실습 노트를 본인 것으로 바꿔 입력한다.

내 볼트: [실제 볼트 경로]
실습 노트: [비민감 노트 경로]

네 실행 환경이 내 PC인지 원격·WSL인지 확인하고,
위 볼트에 접근할 수 있는지 점검해줘.
볼트 작업 지침을 먼저 읽고, 지정한 노트의 제목·속성·첫 문장을 보여줘.
파일이나 설정은 변경하지 마.

읽기 확인 후 새 파일 만들기:

[볼트의 실습 폴더]에 ‘Hermes 연결 확인.md’를 만들어줘.
내용은 ‘에르메스 연결 테스트’ 한 줄로 해줘.
동명 파일이 있으면 멈추고, 다른 파일은 변경하지 마.
저장 경로와 실제 내용을 확인해줘.

→ Obsidian에서 직접 열어 확인한다. 파일 접근과 앱 화면 제어는 별개다.

3. Bases 준비

  • 필수: Obsidian 설정 → 코어 플러그인 → Bases 활성화, AI의 볼트 파일 접근.
  • 권장 스킬: obsidian-bases, obsidian-markdown.
  • 오늘 불필요: QMD·Dataview·MCP. Obsidian CLI는 앱 제어가 필요할 때 선택하며, 앱 실행이 필요하다.

스킬 출처: https://github.com/kepano/obsidian-skills

Claude Code 대화창에서 설치 — 기존 설치 여부부터 확인:

/plugin marketplace add kepano/obsidian-skills
/plugin install obsidian@obsidian-skills

Hermes는 별도로 확인:

현재 Hermes 프로필에서 obsidian-bases와 obsidian-markdown을 사용할 수 있는지 확인해줘.
없으면 https://github.com/kepano/obsidian-skills 의 스킬과 연결된 references를
현재 버전에 맞게 설치하는 방법을 제안하고 승인을 기다려줘.
기존 스킬·설정을 덮어쓰지 말고, 설치 후 새 대화에서 로드되는지 확인해줘.

4. Bases 생성 — 공통 프롬프트

Claude Code 또는 스킬이 준비된 Hermes에서 먼저 입력한다.

내 볼트: [실제 볼트 경로]

obsidian-bases와 obsidian-markdown 스킬을 읽어줘. 없으면 먼저 알려줘.
볼트 지침과 지정한 샘플 노트 3개의 속성을 확인해줘.
실제 필드명·자료형·분류 허용값을 사용해줘.
원본 노트는 수정하지 말고, 새 .base의 저장 위치·열·필터를 제안해줘.
내 승인 후 생성하되 기존 파일은 덮어쓰지 마.
불필요한 성경 구절·설정·휴지통 폴더는 제외해줘.
생성 후 문법을 확인하고, Obsidian에서 표가 열리는지 별도로 확인해줘.
직접 화면을 확인할 수 없으면 나에게 확인을 요청해줘.

A. 최근 생성된 노트

최근 생성순 / 최근 수정순 두 가지 보기를 만들어줘.
열은 노트 이름·생성일·수정일·폴더, 최신 50개로 해줘.
created 속성과 file.ctime 중 어떤 기준을 쓸지 먼저 설명해줘.
날짜가 없는 노트의 처리 방식도 정하고, 대표 노트의 정렬을 확인해줘.

주의: file.ctime은 복사·동기화에 영향을 받을 수 있다. created는 노트에 기록한 날짜다.

B. WORD 분류별 보기

전체 메모 / 작업 중 / 강의용 / 필수 분류 누락 보기를 만들어줘.
World·Outcome·Route·Doctrine 열을 보여줘.
실제 허용값과 목록·단일값·위키링크 자료형에 맞게 필터를 작성해줘.
Doctrine이 필요 없는 노트를 분류 누락으로 판단하지 마.
원본 속성은 변경하지 마.

시연 파일: 0. Bases/최근 생성 파일.base, 0. Bases/WORD 다축 탐색.base.

C. 심방 기록 보기

지정한 실습용 심방 노트의 속성을 확인해 Bases를 만들어줘.
한 행은 심방 기록 한 개로 해줘.
열: 대상·심방일·후속조치일·완료 여부.
보기: 최근 심방순 / 후속 조치 미완료 / 기한 경과 / 심방일 누락.
파일 생성일·수정일을 심방일로 대신 쓰지 마.
누락되거나 잘못된 날짜는 확인 필요로 구분해줘.
상담 본문·전화번호·주소는 읽거나 표시하지 말고 원본은 수정하지 마.

주의: 대상별 그룹화만으로 가정별 최신 기록 한 건만 남지는 않는다. 처음에는 대상별로 묶고 심방일 최신순으로 본다.

5. 꼭 확인할 것

  • 표의 속성을 수정하면 원본 노트도 바뀔 수 있다. 처음에는 필터·정렬 위주로 사용한다.
  • 클라우드 AI에는 읽은 자료가 전달될 수 있다. 실습에는 비민감 자료를 사용한다.
  • Hermes는 무료지만 모델·일부 도구에는 비용과 사용 한도가 있다.
  • 인증정보는 화면 공유하지 않는다. 파일 변경·발송·공개는 승인 후 진행한다.
  • 완료 기준: 노트 읽기 → 새 파일 확인 → Bases 열기 → 포함·제외·정렬 확인.

참고: Hermes Desktop · Bases · 스킬

6. 웹 검색 API 연결

서비스 용도 발급 페이지 Hermes 환경변수
Tavily 웹 검색·본문 추출 https://app.tavily.com/ TAVILY_API_KEY
Firecrawl 본문 추출·검색 https://www.firecrawl.dev/app/api-keys FIRECRAWL_API_KEY
Brave Search 웹 검색 https://api-dashboard.search.brave.com/app/keys BRAVE_SEARCH_API_KEY

검색은 Tavily 또는 Brave, 본문 읽기는 Firecrawl로 역할을 정하면 간단하다. 키를 모두 등록해도 질문마다 최적 서비스를 자동 비교하거나 교차 검증하는 것은 아니다. 검색·추출 기본 설정을 확인한다.

키는 화면 공유를 멈추고 도구 설정란에 입력한다. 채팅·노트에는 저장하지 않는다. 플랜·사용 한도를 확인하며, Brave는 공식 시작 안내상 플랜 활성화에 카드 등록이 필요하다.

키 값은 출력하지 말고, 현재 검색·본문 추출 제공업체를 확인해줘.
검색은 [Tavily 또는 Brave], 추출은 Firecrawl을 쓰고 싶어.
설정 변경이 필요하면 먼저 제안하고 승인을 기다려줘.
준비되면 공개 자료로 검색·본문 추출을 한 번씩 테스트하고,
실제 사용한 서비스·결과 URL·성공 여부를 알려줘. 대체 사용도 밝혀줘.

7. 목회·사역 실시간 검색 프롬프트

대괄호를 본인 상황으로 바꾼다. 검색 결과의 짧은 설명만으로 확정하지 말고 공식 원문을 확인한다.

A. 행사 안내 → 성도용 FAQ

[공개 행사 안내 URL] 한 페이지를 읽고 성도용 FAQ를 최대 7개 만들어줘.
일시·장소·대상·비용·신청 마감·준비물·신청 방법·취소 조건을 확인해줘.
원문에 없는 정보는 ‘주최 측 확인 필요’로 표시해줘.
날짜·금액·신청 링크를 원문과 대조하고 출처를 붙여줘.
초안만 작성하고 발송하거나 게시하지 마.

B. 심방 후 필요한 지역 지원기관

[도시·지역]의 어르신 식사 배달·이동 지원·돌봄 상담 기관을 최대 4곳 찾아줘.
공공기관과 비영리기관 공식 자료를 우선해줘.
기관명·지원 내용·이용 대상·비용·신청 방법·공식 연락처·출처를 표로 정리해줘.
해당 지역 지원 여부와 현재 운영 여부를 확인하고, 불명확하면 ‘기관 확인 필요’로 표시해줘.
특정 성도가 지원 대상이라고 단정하지 마.
전화로 확인할 질문 세 개를 덧붙이고, 개인정보 입력이나 기관 연락은 하지 마.

C. 청소년부 학부모 교육

‘청소년의 스마트폰·SNS 사용과 수면’에 관한 학부모 교육 자료를 찾아줘.
최근 2년 내 발표·업데이트된 공공 보건기관·소아청소년 전문기관 자료 최대 3개를 사용해줘.
기간에 맞는 자료가 부족하면 그대로 알려줘.
공통 권고 세 가지·불확실한 부분·부모와 자녀의 대화 질문 네 개·일주일 실천 두 가지를 정리해줘.
통계에 조사 대상·연도·출처를 붙이고, 상관관계를 원인으로 단정하지 마.
공식 권고와 네 활동 제안을 구분하고, 개별 청소년을 진단하지 마.

D. 설교에 쓸 통계·인용 검증

설교에서 다음 주장을 인용해도 되는지 검증해줘: [문장 그대로]
최초 연구·공식 보고서·당사자 원문을 찾아줘.
확인됨 / 일부만 확인됨 / 근거 부족으로 판정하고 출처·발표일·원문 근거를 제시해줘.
통계는 국가·대상·표본·연도, 인용은 실제 발언인지 후대의 요약인지 확인해줘.
과장·빠진 조건과 설교에서 사용할 신중한 표현을 알려줘.
근거가 없으면 출처나 대체 예화를 만들어내지 마.

E. 교단 공식 입장과 개인 의견 구분

[교단·기관명]의 [주제] 관련 자료를 찾아줘.
총회 결의·공식 지침 / 산하기관 교육 자료 / 소속 인사 개인 의견을 구분해줘.
제목·발표 주체·날짜·문서 성격·핵심·원문 URL을 정리해줘.
채택 문서인지 제안·토론 문서인지 확인하고, 개인 의견을 교단 공식 입장으로 표현하지 마.
공식 입장을 못 찾으면 ‘공개 자료에서 확인하지 못함’이라고 써줘.
교회 교육에 사용할 때 주의할 점 두 가지를 제안해줘.

F. 예배·주보·영상의 저작권 확인

[국가]의 교회에서 [자료·서비스]를 [현장 예배 / 생중계 / 녹화본 게시 / 주보]에 쓰려고 해.
권리자·라이선스 기관의 공식 안내를 찾아 사용 방식별 조건·필요한 허락·불명확한 부분·출처를 정리해줘.
무료 열람과 무료 재사용, 현장 사용과 생중계·녹화 게시를 구분해줘.
정보가 부족하면 먼저 질문하고, 법률적 확답 대신 권리자에게 확인할 질문과 공식 문의 경로를 제시해줘.
신청·결제·게시 작업은 하지 마.

공통 마무리 질문

실제 원문으로 확인한 사실과 네 제안을 나눠줘.
중요한 날짜·금액·인용은 근거 문장과 URL을 보여줘.
읽지 못했거나 확인하지 못한 부분도 밝혀줘.

직접 확인: 대표 원문 한 개를 열어 답변과 대조한다. AI의 재점검만으로 정확성이 보장되지는 않는다. 지역 지원·저작권 판단은 관련 기관의 확인을 받는다.
